# Translate Technical Document

請使用 `technical-translator` Subagent 將指定的英文技術文件翻譯成繁體中文。

## 參數

- `$1`：來源文件路徑，必填。
- `$2`：輸出文件路徑，選填。

## 執行規則

請將：

`$1`

翻譯成繁體中文。

如果 `$2` 有提供，請將翻譯結果輸出至：

`$2`

如果 `$2` 沒有提供，請依下列規則自動建立繁體中文版檔名：

- `README.md` → `README.zh-TW.md`
- `guide.md` → `guide.zh-TW.md`
- `docs/install.md` → `docs/install.zh-TW.md`
- `docs/api-reference.md` → `docs/api-reference.zh-TW.md`

原則上，請在原始檔名副檔名前加入：

```text
.zh-TW
```

例如：

```text
docs/setup.md
```

應輸出為：

```text
docs/setup.zh-TW.md
```

## 翻譯要求

- 使用繁體中文。
- 使用台灣常用的技術用語。
- 保留原始 Markdown 結構。
- 不修改程式碼區塊。
- 不修改 CLI 指令。
- 不修改 Shell 指令。
- 不修改 API 名稱與 endpoint。
- 不修改 URL。
- 不修改 JSON key。
- 不修改 YAML key。
- 不修改變數名稱。
- 不修改函式名稱。
- 不修改類別名稱。
- 不修改套件名稱。
- 不修改環境變數。
- 不修改檔案路徑。
- 不修改產品、框架、服務與技術名稱。
- 重要技術術語第一次出現時，可使用「中文名稱（English Term）」格式。
- 若直接保留英文術語更清楚，則保留英文。
- 不可自行增加原文沒有的內容。
- 不可省略原文內容。
- 不可改變原文技術含義。
- 除非使用者明確指定，否則不得覆寫原始英文文件。

## 文件處理規則

開始翻譯前：

1. 先完整讀取來源文件 `$1`。
2. 確認文件格式與結構。
3. 確認 Code Fence、表格、連結、Front Matter 等區塊。
4. 僅翻譯自然語言內容。
5. 保留所有技術識別字與程式碼。

如果來源文件不存在、無法讀取或路徑不正確，停止執行並清楚回報原因，不要自行猜測檔案位置。

## 輸出

完成後請回報：

1. 原始文件路徑。
2. 產生的繁體中文文件路徑。
3. 是否完整保留 Markdown 結構。
4. 是否完整保留程式碼與 CLI 指令。
5. 是否有遇到無法確定的技術術語或原文疑似錯誤。

如果發現原文可能有技術錯誤或版本差異，不要直接修改原意，可在翻譯文件中使用：

```markdown
> 譯註：原文此處可能存在技術或版本差異，建議確認官方文件。
```

但只有在確有必要時才加入譯註。
