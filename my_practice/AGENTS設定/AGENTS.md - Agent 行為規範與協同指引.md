# AGENTS.md - Agent 行為規範與協同指引

本檔案定義自主 Agent（如 Claude Code, Cursor, Copilot 等）在進入本專案工作時必須遵守的角色職責、工具邊界、完成定義（DoD）與中斷機制。

---

## 1. 角色職責與分工 (Role & Responsibility)

- **預設模式**：維持單一 Agent 貫徹「分析 ➔ 執行 ➔ 自我驗證 ➔ 交付」完整閉環，避免不必要的上下文切換。
- **角色行為規範**：
  - **Planner（規劃）**：遇到涉及 3 個以上模組或架構異動時，必須先列出繁體中文「執行計畫（Action Plan）」與受影響範圍，經由人類確認後方可動工。
  - **Executor（執行）**：嚴格遵循現有專案架構與程式碼風格，僅修改與目標直接相關的檔案，嚴禁未經授權重構周邊代碼。
  - **Validator（驗證）**：負責運行測試與靜態檢查，提出客觀數據證明任務達標。

---

## 2. 專案背景與上下文範圍 (Context & Rules)

### 讀取邊界 (Read Boundary)
- **必須優先閱讀**：
  - 本檔案 (`AGENTS.md`)
  - 專案依賴與設定 (`package.json` / `pyproject.toml` / `requirements.txt` 等)
  - 相關模組的型別定義與既有單元測試檔案
- **忽略/排除範圍**：
  - 嚴禁主動檢索或將大型日誌檔 (`*.log`)、建置產物 (`dist/`, `build/`)、快取檔案塞入 Context。

### 架構與編碼鐵則 (Non-negotiables)
1. **型別安全**：所有新增/修改的函式均需具備完整的靜態型別定義（如 TypeScript 嚴格型別、Python Type Hints），禁止使用 `any` 或弱型別逃逸。
2. **無破壞性修改**：若非任務要求，不得擅自升級第三方相依套件版本或修改全域環境設定。
3. **中文註解與語系**：面向使用者的訊息與核心註解一律採用繁體中文（台灣習慣用語）。

---

## 3. 工具權限與操作邊界 (Tool Permissions & Human-in-the-Loop)

Agent 在呼叫工具與執行終端指令時，必須嚴格遵守以下分級權限：

| 權限層級 | 操作類型 | 允許行為 / 觸發條件 |
| :--- | :--- | :--- |
| **完全自動 (Auto-approved)** | 唯讀 / 本機驗證 | - 搜尋、讀取檔案內容<br>- 執行單元測試 (`npm test`, `pytest`)<br>- 執行靜態檢查/格式化 (`eslint`, `ruff`, `prettier`) |
| **自動（限本機/工作區）** | 程式碼修改 | - 修改任務範圍內的原始碼<br>- 新增對應的單元測試檔案 |
| **必須人工授權 (Approval Required)** | 破壞性 / 外部操作 | - 安裝、移除第三方相依套件 (`npm install`, `pip install`)<br>- 執行任何資料庫 Migration、Drop、清空操作<br>- 呼叫外部未授權之第三方 API 或外部連線<br>- 執行刪除目錄/檔案之指令 (`rm -rf` 等)<br>- Git Push 或對主分支（main/master）進行強制覆寫 |

---

## 4. 完成定義 (Definition of Done, DoD)

Agent 宣稱「任務完成」前，**必須提供以下客觀驗證證據**，不得僅憑口頭推論：

1. [ ] **自動化測試通過**：執行專案測試指令，所有受影響與關聯的單元測試/整合測試為 **100% 通過（Green）**。
2. [ ] **靜態檢查零報錯**：執行 Linter 與 Type Check，無任何新增的 Error 或 Warning。
3. [ ] **改動最小化確認**：檢視 `git diff`，確認無遺留無用的除錯程式碼 (`console.log`, `print`)，無未授權的排版異動。
4. [ ] **交付說明**：於對話中提供結構化交付總結：
   - **修改重點摘要**：簡述改動核心邏輯。
   - **客觀驗證指令與結果**：列出執行的測試指令與過關輸出截圖/摘要。

---

## 5. 回復機制與故障熔斷 (Rollback & Failure Circuit Breaker)

為避免 Agent 陷入死循環修補並污染工作區，必須嚴格落實防護網：

### 工作區回復點 (Checkpoint)
- 進入任務前，必須確認目前 Git 工作目錄處於乾淨狀態（Clean Working Tree）或已切換至獨立實驗分支（如 `feature/agent-*`）。
- 一旦方向偏差或修改徹底失敗，必須能隨時執行 `git checkout .` 或 `git reset --hard` 回復現場。

### 故障熔斷規則 (Circuit Breaker)
1. **重試次數限制**：在面對同一個報錯或測試失敗時，**最多允許自主嘗試修復 2 次**。
2. **連續失敗處置**：
   - 若連續 2 次修改後測試依然失敗，**強制停止自主執行**。
   - 嚴禁繼續盲目嘗試或隨機修改無關代碼。
   - 必須將當前控制權交還人類，並輸出以下診斷報告：
     ```markdown
     ### 🚨 執行中斷與診斷回報
     1. **當前核心目標**：...
     2. **遭遇的根本阻礙**：詳細報錯訊息與根本原因推測。
     3. **前 2 次嘗試失敗的分析**：說明嘗試過的方法為何無效。
     4. **需要人類決策或補充的資訊**：請求架構確認、缺失資訊或指示是否重整問題。
     ```
