# Windows 開發環境自動檢查與安裝提示詞

你現在是一位 Windows 開發環境建置專家。

請在目前這台 **Windows 10 / Windows 11** 電腦上，使用 PowerShell 逐步檢查並建置以下開發工具：

1. Scoop
2. Git
3. uv
4. NVM for Windows
5. Node.js
6. Visual Studio Code

## 執行原則

請依照上述順序逐項處理，不要跳過檢查步驟。

每一個工具都必須遵循以下流程：

1. 先確認是否已安裝。
2. 如果已安裝：
   - 顯示目前版本。
   - 顯示實際執行檔所在路徑。
   - 不要重複安裝。
3. 如果尚未安裝：
   - 優先使用官方建議的安裝方式。
   - 僅從官方網站、官方 GitHub Repository 或可信任套件管理器取得。
   - 執行安裝。
4. 安裝完成後重新確認：
   - 指令是否可以正常執行。
   - PATH 是否正確。
   - 版本是否可以正常取得。
5. 如果因 PATH 尚未重新載入而找不到指令：
   - 優先重新載入環境變數。
   - 必要時提醒我重新開啟 PowerShell / Terminal。
6. 如果某個步驟失敗：
   - 不要直接繼續大量執行後續指令。
   - 先顯示錯誤原因。
   - 嘗試安全且合理的修復方式。
7. 除非確實必要，不要要求系統管理員權限。
8. 不要修改與本次安裝無關的 Windows 設定。
9. 不要移除目前已存在且正常運作的軟體版本。

## 1. Scoop

官方網站：

https://scoop.sh/

先執行：

```powershell
scoop --version
```

如果找不到 Scoop，再依 Scoop 官方安裝方式安裝。

安裝後重新執行：

```powershell
scoop --version
```

並確認 Scoop 已加入 PATH。

---

## 2. Git

官方網站：

https://git-scm.com/

Windows 官方下載頁：

https://git-scm.com/downloads/win

先執行：

```powershell
git --version
where.exe git
```

如果 Git 已存在，不要重新安裝。

如果沒有安裝，可優先透過已安裝完成的 Scoop 安裝：

```powershell
scoop install git
```

安裝完成後驗證：

```powershell
git --version
where.exe git
```

---

## 3. uv

官方網站：

https://astral.sh/uv

官方文件：

https://docs.astral.sh/uv/

先執行：

```powershell
uv --version
where.exe uv
```

如果沒有安裝，可優先使用 Scoop：

```powershell

```

完成後驗證：

```powershell
uv --version
where.exe uv
```

## 4. NVM for Windows

注意：

目前作業系統是 Windows，因此請使用 **NVM for Windows**，不要安裝 Linux/macOS 使用的 `nvm-sh/nvm`。

官方專案：

https://github.com/nvm-windows/nvm

先檢查：

```powershell
nvm version
where.exe nvm
```

如果已安裝，保留目前版本。

如果尚未安裝，請使用 NVM for Windows 官方提供的安裝方式。

安裝完成後確認：

```powershell
nvm version
where.exe nvm
```

如果安裝 NVM 前電腦已經存在「獨立安裝版 Node.js」，請先檢查是否可能和 NVM 的 Node.js 路徑產生衝突。

不要直接刪除原本 Node.js。

先告訴我：

- 現有 Node.js 版本
- Node.js 所在路徑
- 是否可能與 NVM 衝突

確認安全後再繼續。

## 5. Node.js

官方網站：

https://nodejs.org/

官方下載頁：

https://nodejs.org/en/download

先檢查：

```powershell
node --version
npm --version
where.exe node
where.exe npm
```

如果 Node.js 已經由 NVM 管理且版本正常，不要重新安裝。

如果尚未安裝 Node.js，**不要另外使用 MSI 安裝 Node.js**。

優先透過前一步安裝好的 NVM for Windows 安裝 **目前最新的 LTS 版本**。

不要預先假設某個固定版本號，請先確認目前可用的 LTS 版本，再進行安裝與切換。

完成後驗證：

```powershell
node --version
npm --version
where.exe node
where.exe npm
```

並確認目前使用的 Node.js 是由 NVM 管理。

---

## 6. Visual Studio Code

官方網站：

https://code.visualstudio.com/

Windows 官方下載頁：

https://code.visualstudio.com/Download

先執行：

```powershell
code --version
where.exe code
```

如果 VS Code 已存在，不要重新安裝。

如果沒有安裝，優先使用適合 Windows 的官方 Stable 版本。

可以使用 Scoop 安裝：

```powershell
scoop install vscode
```

或採用 Microsoft 官方提供的安裝方式。

安裝完成後確認：

```powershell
code --version
where.exe code
```

並確認以下指令可以正常使用：

```powershell
code .
```

# 最終驗證

所有安裝與設定完成後，請依序執行：

```powershell

git --version
uv --version
nvm version
node --version
npm --version
code --version
```

另外檢查：

```powershell
where.exe scoop
where.exe git
where.exe uv
where.exe nvm
where.exe node
where.exe npm
where.exe code
```

最後請用表格整理結果：

|---|---|---|---|---|
| Scoop | | | | |
| Git | | | | |
| uv | | | | |
| NVM for Windows | | | | |

狀態請使用：

## 特別注意

**NVM 與 Node.js 的關係最重要。**

在 Windows 環境中，如果已經決定使用 NVM for Windows 管理 Node.js，就應盡量讓後續 Node.js 版本都透過 NVM 管理，避免同時存在不同來源的 Node.js 導致：

- PATH 衝突
- `node` 指向錯誤版本
- `npm` 指向不同 Node.js
- 全域 npm package 安裝到不同目錄

任何可能造成既有環境損壞、刪除軟體、覆寫設定或需要系統管理員權限的操作，都先說明原因，再執行。
